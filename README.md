# ClusterBoard v0.11 — удобство и надёжность существующих разделов

Версия реализует 12 замечаний из UI/UX-ревью v0.10.1. Состав разделов и бизнес-правила не менялись: «Люди и команды», «Цели квартала», «Инициативы». Нового backend, авторизации или синхронизации нет.

## Проектирование серверной части

[Спецификация backend API и SQLite](docs/backend-api.md) — контракт для последующей реализации всех трёх разделов портала. В документе описаны модель данных, HTTP API, права, сессии, транзакционные команды, версии структуры, общие цели, инициативы и Гант, защита от конфликтов, перенос из localStorage, резервное копирование и критерии приёмки.

Это **документация будущей реализации**, а не уже подключённый backend. Изменение документации не меняет работу текущего HTML. Выбранная архитектура: один сервис API и обычный SQLite на локальном постоянном диске; сервер становится источником бизнес-данных только после реализации API и подключения фронтенда.

## Обновление хостинга

1. В действующей версии выгрузите JSON через меню данных. Сохраните прежние `index.html` и `version.json` отдельно.
2. Из этого архива скопируйте `index.html` и `version.json` в каталог, который обслуживает веб-сервер. Для ранее обсуждавшегося репозитория это `public/index.html` и `public/version.json`, а не корень Git-репозитория.
3. Откройте `http://176.123.167.199/?v=0.11#/initiatives/registry`.
4. Проверьте отметку **v0.11 в самом интерфейсе**, прежних сотрудников, назначения, цели и инициативы. Параметр `?v=0.11` в адресе сам по себе не обновляет HTML.
5. После обновления ещё раз экспортируйте JSON. Данные сайта очищать не нужно.

Архив не был установлен на сервер автоматически. Изменений в Git в этой итерации не отправлялось. Для статического размещения не нужна сборка, CDN или дополнительные библиотеки; все стили, скрипты и иконки находятся в HTML.

На другом домене, протоколе, устройстве или при открытии нового локального файла данные могут находиться в другом хранилище: используйте экспорт/импорт JSON. Импорт заменяет текущий набор — сначала сохраните резервную копию. Просмотр HTML как вложения не заменяет запуск страницы в браузере.

## Люди и команды

Поиск на экране сотрудников фильтрует по ФИО, роли и команде. Нажатие на сотрудника открывает единую карточку со всеми назначениями, продуктами, целями и инициативами. ФИО меняется в карточке человека, а роль/процент — в конкретной позиции.

На зависимых экранах явно указан срез «Текущая / Будущая». Общий справочник людей доступен для дополнения в обоих срезах. Назначения и настройки команды изменяются только в будущем плане. Редактирование ФИО не создаёт нового человека и не меняет его ссылки.

На обычной карте доступны настройки команды/стрима. Из карточки позиции можно открыть её в будущем плане, посмотреть человека или перейти к перераспределению. В режиме «Только структура» редакторские действия не показываются.

## Цели

В существующей цели сразу видны прогресс, состояние и комментарий. Реквизиты, история и команда исполнения отделены. Сохранение и отмена находятся внизу формы. Новая цель по-прежнему создаётся отдельной формой; общие цели, ответственный и исполнители, ДОП-отметка и проценты сохранены.

## Инициативы и Гант

Реестр и календарь получили компактную шапку. Второстепенные фильтры, порядок сортировки, давность обновления и демоподсказки раскрываются по кнопке «Фильтры». Основные показатели работают как прежде.

В коротком обновлении сначала видны четыре поля: статус, прогресс, содержательное обновление, следующий шаг. Риски, даты и ответственные доступны ниже. При состоянии «Заблокирована» автоматически появляется поле блокера. Изменение периода по-прежнему требует причины и фиксируется в истории.

На Ганте действие называется **«Показать Гант»**, карточный показ — **«Карточки инициатив»**. Масштабы, группировки и чтение подробностей сохранены. Переноса полос с изменением дат не добавлено.

## Поведение форм

Изменённая форма защищена при Esc, нажатии на фон/отмену и переходе в другой раздел. Диалог предлагает продолжить ввод или отказаться от несохранённого. Неизменённая форма закрывается без вопроса. При уходе со страницы используется также штатное предупреждение браузера; оно зависит от ограничений браузера и не является резервной копией.

Ошибки показываются списком и рядом с полями, нужная секция раскрывается, фокус переходит к исправлению. Обязательность зависит от состояния: черновик не требует реквизитов рабочей инициативы.

Надпись «Есть несохранённые изменения» отличается от сохранённого состояния. Если запись отклонена (включая имитацию переполнения хранилища), проверенные операции возвращают исходную модель и сохраняют введённый черновик для повторной попытки. При обнаруженном конфликте вкладок новая запись блокируется. Это защита локального прототипа, не полноценное многопользовательское блокирование на сервере.

Для увеличенного системного шрифта, произвольных длинных данных и других размеров эти числа не гарантируются; интерфейс сохраняет прокрутку и доступ к полным карточкам. Имена, даты и ключевые статусы получили более читаемый размер и контраст. Основные проверенные мобильные кнопки имеют высоту не менее 44px.

## Проверка непосредственно после установки

Откройте сотрудников, найдите человека и проверьте его карточку. В будущей структуре измените описание позиции; текущая должна остаться прежней. Откройте продукт, введите пробный текст, нажмите Esc и выберите продолжение — текст должен остаться. Обновите тестовую цель с комментарием, перезагрузите страницу и проверьте значение. В инициативе откройте короткое обновление и проверьте раскрытие сроков; затем откройте Гант и режим показа. Повторите ключевые действия в Safari на используемом устройстве до переноса реальной работы.
